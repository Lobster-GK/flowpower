# 启动检查阶段

所有输出使用中文。

## 使用场景

- 用户要求执行启动检查。

本 Skill 只负责启动检查动作本身：启动项目、理解日志、修复并重试。

## 特别说明

启动操作的shell 命令不会自动结束，你只需要判断输出中是否包含明确的错误信息或者明确的成功信息即可，成功的信息示例: successfully。

启动命令以及端口号获取方式：
- 启动命令
  检查package.json，查看是否存在 `start` 、`dev` 等和本地启动相关的指令，有则使用，无法确定时**必须停下来询问用户启动命令**
- 启动端口
  检查启动命令后方是否存在 `--port` 等和端口号配置相关的参数，有则使用用户配置的端口，没有就查看启动命令执行结果，是否输出本地服务地址和端口

<EXTREMELY-IMPORTANT>
**重要约束：如果发现用户已经启动过本地服务，严格禁止杀掉已启动服务，这时必须使用 question 工具询问用户**
question 工具配置如下：
```yaml
header：编译检查
question：请检查编译服务是否存在编译报错或影响运行的警告，确认后反馈结果
options：
  - label: 无编译错误
    description: 编译通过，无编译错误
  - label： 有编译错误
    description： 项目存在编译错误，请提供错误信息。
mutiple： false
```
**用户选择`无编译错误`，你必须直接结束启动检查，执行后续流程。**
**用户选择`有编译错误`, 你必须请用户补充错误信息，根据错误信息进行修复，修复后重新执行启动检查。**
</EXTREMELY-IMPORTANT>

## 执行流程

1. 检查项目是否安装依赖(判断是否存在node_module目录且目录下有依赖包)，如果已安装，则执行 `yarn start`，未安装则执行 `yarn --ignore-enginess` 安装依赖，安装完毕执行 `yarn start`。
2. 启动成功时，记录返回的 URL。
3. 启动失败时，读取日志尾部和完整日志产物。
4. 使用 `frontend-error-fix` skill，只修复相关文件。
5. 修复后再次执行启动检查，直到通过或确认被阻塞。

## 修复约束

- 优先修复缺失导入、模块路径、组件导出、语法编译错误、样式资源路径错误。
- 不要修改全局启动脚本或构建配置来掩盖本次生成代码问题。
- 不要随意新增依赖；如果必须新增，先确认项目已有依赖管理方式。
- 不要删除主要 UI 结构来规避编译错误。
- **非常重要：如果有警告，含义是： export <api> was not found in <package>；你必须尝试修复**


## 修复说明

当循环修复5次以上依然不能解决问题，直接退出并报告给用户
