# 启动检查阶段

所有输出使用中文。

## 使用场景

- 用户只要求执行启动检查。
- 用户通过 `/afp-boot-check` 命令进入启动阶段。
- apollo-flowpower 自动化流程进入 boot 阶段。

本 Skill 只负责启动检查动作本身：启动项目、理解日志、修复并重试。不要在本 Skill 内继续运行时检查；需要全流程编排时，由 `/afp-scene` 显式触发并加载的场景模板 YAML 决定下一阶段。

## 执行流程

1. 如果需要为本阶段指定模型，优先查看 `afp_get_project_config` 返回的 `subagents` 中 `afp-verifier-agent.model`；为空时继续使用当前会话默认模型。
2. 优先按用户明确给出的启动命令执行；如果用户未指定，读取 `package.json` scripts，优先使用 `start`，其次使用 `dev`。
3. 启动服务前不要读取或依赖 apollo-flowpower 私有启动配置；本版本没有 devServer 配置。
4. 捕获本次启动命令的日志，判断是否出现编译错误、端口错误、模块导入错误、类型错误或依赖缺失。
5. 如果启动失败，整理错误摘要并使用 `frontend-error-fix` skill 只修复本次生成目录内文件。
6. 修复后再次执行启动检查，直到通过或确认需要用户处理外部环境。

## 修复约束

- 优先修复缺失导入、模块路径、组件导出、语法编译错误、样式资源路径错误。
- 不要修改全局启动脚本或构建配置来掩盖本次生成代码问题。
- 不要随意新增依赖；如果必须新增，先确认项目已有依赖管理方式。
- 不要删除主要 UI 结构来规避编译错误。
